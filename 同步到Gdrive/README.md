# 手动同步到 Google Drive 副本

双击本目录的 [run_sync.bat](run_sync.bat)，把 `C:\Users\15919\Desktop\论文草稿` 的当前磁盘文件单向更新到 `C:\Users\15919\Desktop\论文草稿-Gdrive`。窗口显示完成后按任意键关闭。运行依赖 Windows PowerShell 5.1 和 PATH 中的 Git，不需要 Python。

Google Drive 桌面版需单独将 `论文草稿-Gdrive` 配置为同步文件夹。本脚本只维护本地副本；窗口显示完成表示本地复制完成，云端上传状态由 Google Drive 桌面版显示。脚本不启动后台定时任务。

## 文件选择和更新规则

- 已跟踪文件和未跟踪文件都按当前 Git 忽略规则筛选，包括 `.gitignore`、嵌套忽略文件、仓库本地排除规则和全局排除规则。已跟踪但当前被忽略的文件也排除。
- 复制已经保存到磁盘的最新内容，不需要 commit 或 push；未保存的 Word、PPT、编辑器内容需要先保存。
- 固定排除 `.git`、根目录 `temp/`、各级 `.tmp.driveupload/` 和 `.tmp.drivedownload/`，它们分别保存仓库内部信息、运行中间文件和 Drive 内部临时文件。
- 通过 SHA256 内容摘要比较文件；内容不同才替换。副本中与源文件同名的修改会被源文件覆盖，覆盖前的副本保存到本次运行的 `replaced/`。
- 原先同步过的文件在源目录删除、重命名或被忽略后，下次运行将旧副本移入本次运行的 `removed/`。重命名体现为新增新路径、移出旧路径。
- 副本中额外添加、且从未进入同步清单的文件保留。同名文件将由源文件接管。空目录不作为同步对象，也不主动清理旧空目录。
- 状态清单丢失时按首次运行处理：更新当前源文件，保留无法确认归属的额外文件。
- 源稿、PPT、Git 索引和提交历史不被回写；所有日志、清单和备份只写在源目录的 `temp/gdrive-sync/` 下。

源目录和目标目录必须同盘、互不包含，并使用普通目录；符号链接、目录联接、云端占位重解析点及 Git 子模块不自动展开。普通硬链接按文件内容复制，替换副本不会透过硬链接改写源文件。复制或文件占用导致失败时窗口显示失败并返回退出码 `1`；下一次可重新运行。一次运行不是跨多个文件的整体事务，失败前完成的副本更新可能已经生效，旧清单仅在整轮成功后更新。

## 入口和运行文件

```text
论文草稿/
├─ 同步到Gdrive/
│  ├─ run_sync.bat          # 双击入口，执行后停留窗口显示结果
│  ├─ sync_to_gdrive.ps1   # Git 筛选、内容比较、单向复制和状态维护
│  └─ README.md            # 使用方法和文件契约
└─ temp/gdrive-sync/<目标路径摘要>/
   ├─ state.json           # 最近一次完整成功运行的文件清单
   ├─ sync.lock            # 防止两个进程同时更新同一副本
   └─ run-<时间>-<随机后缀>/
      ├─ sync.log          # 本次控制台日志
      ├─ previous-state.json  # 更新前的状态清单，首次运行没有此文件
      ├─ staged/           # 写入副本前的完整暂存文件，成功写入后移走
      ├─ replaced/         # 本次被覆盖的副本文件，保留原相对路径
      └─ removed/          # 本次因源文件删除或忽略而移出的副本文件
```

`<目标路径摘要>` 是目标绝对路径转为小写后计算的 SHA256 前 16 个十六进制字符，使不同副本拥有独立状态。`run-<时间>-<随机后缀>` 如 `run-20261019-223000-123-a1b2c3`，每次运行单独保存日志。`staged/`、`replaced/` 和 `removed/` 只在实际需要时创建。预览运行仅创建锁、运行目录和日志。

`state.json` 为 JSON 对象，字段如下：

| 字段 | 类型与具体含义 | 示例 |
|---|---|---|
| `version` | 整数，当前清单格式版本 | `1` |
| `source` | 字符串，源仓库绝对路径 | `C:\Users\15919\Desktop\论文草稿` |
| `destination` | 字符串，本清单管理的副本绝对路径 | `C:\Users\15919\Desktop\论文草稿-Gdrive` |
| `files` | 字符串数组，已同步文件相对于源根目录的路径；空数组表示没有文件 | `["draft.md", "画图/stage1结果.pptx"]` |

维护时从 `run_sync.bat` 查看启动方式，再从 `sync_to_gdrive.ps1` 的末尾主流程查看默认路径、文件清单和备份位置；文件选择集中在 `Get-SyncFiles`，边界检查集中在 `Get-ChildPath` 和 `Assert-PlainPath`。

## 命令行预览

在仓库根目录执行以下命令，查看计划更新或移出的文件，不改副本和成功状态清单：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\同步到Gdrive\sync_to_gdrive.ps1" -DryRun
```

脚本默认从自身位置推导源目录，目标为同级的 `<源目录名>-Gdrive`。验证用的独立 Git 仓库可通过 `-SourceRoot` 和 `-DestinationRoot` 显式指定；两个路径仍需同盘且互不包含。
