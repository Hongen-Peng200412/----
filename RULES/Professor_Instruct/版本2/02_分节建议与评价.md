## 方法总览与论文定位

### O01｜Overview 解释方法思想，减少严格定义和形式化细节

- **导师意思：** Overview 应让读者从输入、总体思路和各阶段作用理解方法，围绕总览图展开；当前包含的严格定义和细节超出了概述的职责。建议参考 Nature 系列论文，尤其对话中提到的 CryoAtom2 的相关写法。
- **作者回应：** 询问这里是否还要介绍数据集和测评；导师回答这应放在 Results，Overview 主要概括方法。作者作简短回应，尚未给出具体改稿方案。
- **当前对应：** 中文正文 Overview 中的原子集合、50 维特征、56 通道张量、Find/Match 数学表达，以及末尾测试集与评价说明。
- **评价与建议：** 建议优先采纳。保留密度与受体信息互补、Find–Match–Build 的职责和输入输出；严格符号及网络细节进入 Methods，评测样本和评价任务进入 Results 的相应位置。概述仍须交代候选配体身份由用户提供，这属于读者理解任务所需的输入条件。
- **来源：** A 05:10–07:22；并参考附录中的第一段外部识别。

### N01｜导师反对将分阶段串联直接称作“端到端”

- **导师意思：** 当前方法是分别完成多个阶段后把流程连接起来；按他在对话中采用的含义，“端到端”应当是从输入直接得到最终结果的整体模型或算法，不应以该词夸大分阶段流程。
- **作者回应：** 明确说可以把“端到端”的修饰词去掉，之后又作肯定回应。这比简单的“嗯”具有更明确的接受含义。
- **当前对应：** Abstract、Introduction、端到端 Results、Methods 及关联图注和标签；具体改名范围仍待作者确定。
- **评价与建议：** 建议优先采用“全自动建模流程／自动化工作流”描述已展示的能力。导师采用的是较严格的术语含义；“多阶段流程”与“流程级端到端评测”并非在所有文献中互斥，因此不把他的说法扩写成领域公认定义。需要作者决定：只改方法宣传性称谓，还是连实验小节的任务名称一并调整。评价逻辑和实验数据无需因改名而改变。
- **来源：** A 04:08–05:39。

## 总览图与架构图

### F01｜明确受体结构可以从密度经 CryoAtom2 获得

- **导师意思：** 总览图应同时表现两种受体来源：直接提供结构，或者由 CryoAtom2 预测；需要把从密度到自动重建受体的关系画出来。
- **作者回应：** 提议加箭头和虚线，导师认可这种表达方向。
- **评价与建议：** 建议采纳。用两条清晰输入路径表达两种条件，避免把自动重建受体画成无来源的输入。线型含义需要在图内或图注中明确。
- **来源：** A 00:10–00:51；对应 `fig-overview_v2`。

### F02｜把候选身份列为明确输入，并区分 SMILES 与化学结构图

- **导师意思：** 候选配体身份不能在 Match 处突然出现；它是外部输入。SMILES 是字符串，二维化学结构图本身不能直接标作 SMILES。
- **作者回应：** 最初说可以改为字符串；后来提出统一写成 ligand identity，让二维图或卡通图都能解释。导师未接受用宽泛标签绕过具体输入的表达，仍强调正确展示 SMILES。
- **评价与建议：** 建议采纳输入来源与表示形式的区分。输入层展示实际 SMILES；分子图分支可展示由它生成的化学图，并标出转换关系。标题可以使用“候选配体身份”，但具体表示不能因此混同。
- **来源：** A 00:45–01:33、13:20–14:34；对应总览图和 `fig-method-v8` 的 Match 部分。

### F03｜用真实、可解释的配体和表面代替随手画的形状

- **导师意思：** 当前部分图形像手绘草图，缺乏专业感；可用真实配体结构和透明表面表现形状，使读者理解比较对象。他在解释中提到了构象、形状相似性或互补性。
- **作者回应：** 担心三维图会被读者理解为真实空间中的结合构象；对话中继续讨论了可用的表示方式，没有形成完整的最终图稿。
- **评价与建议：** 支持替换难以解释的卡通形状，同时保留作者的科学顾虑：若展示由 SMILES 构造的理想构象，应明确它不是参考结合构象。导师关于形状的图示解释不能直接改写为 Match 网络的唯一计算机制；实际模型还包含语言表示、分子图和上下文信息。
- **来源：** A 00:59–02:02。

### F04｜不同候选 blob 的形状应有区别，并能追溯到原始密度中的位置

- **导师意思：** B1、B2 来自不同空间区域，不应画得完全一样；从整图取出的候选应能看到其原始位置，图一和后续架构图采用相互一致的表示。
- **作者回应：** 表示会调整候选形状，并认可在原图中标注位置的方向。
- **评价与建议：** 建议采纳。可用同一真实示例连接全图、候选区域和局部放大，候选编号跨图保持对应。示意差异不应伪装成真实预测；真实结果应来自同一案例的正式产物。
- **来源：** A 02:16–02:31、11:50–13:19。

### F05｜主流程图突出实际微调的 Build 模型，是否保留其他对接工具存在讨论

- **导师意思：** 主图中不必列出多个并非本文实际开发或验证的 docking 工具，应集中展示自己微调的 PocketXMol 及其构建过程。
- **作者回应：** 解释列出其他工具是为了说明 Build 可插拔：Find 与 Match 支持金属、糖等类型，而默认微调模型只支持小分子，可由其他适用工具承接。导师继续追问其他工具是否确实支持这些类型，没有形成对所有替代工具的逐项确认。
- **评价与建议：** 建议主图聚焦已经验证的默认流程；在 Methods 或图注简短交代模块接口。作者关于可扩展性的理由应保留，但“可以接入”与“已完成所有配体类型的构象重建”是两项不同命题。需要核查列出的每个工具的适用对象，不能由接口存在推导已经验证的全类型能力。
- **来源：** A 02:30–04:13。

### F06｜最终输出展示真实全原子结构，必要时局部放大

- **导师意思：** 当前虚构输出图不足以说明模型真正产生的结果；可以展示真实结构，并放大一个配体让结果看得清。
- **作者回应：** 提到真实结果可能不好画，之后作简短应答；具体案例尚未在这段对话中确定，不能据此记为完整方案已获认可。
- **评价与建议：** 建议采纳。优先使用已有完整链条的案例，保证输出结构与前面的密度、受体和候选指向同一对象。
- **来源：** A 02:54–03:39。

### F07｜去掉缺乏功能含义的字体和边框颜色

- **导师意思：** 当前绿色文字、边框等装饰色显得多余，读者无法从颜色推断不同功能；应简化，文字可统一为黑色。
- **作者回应：** 询问框是否还要用颜色；导师强调只有在区分功能时颜色才有意义，作者随后简短回应，没有逐项确认配色改法。
- **评价与建议：** 建议采纳“颜色承担明确语义”的原则。文字统一黑色，保留少量用于密度、受体、候选或不同信息流的颜色即可；不需要把所有科学图形都强制改为黑白。这里的“黑色”不能误记为要求所有字体都加粗。
- **来源：** A 07:22–08:17；重点对应 `fig-method-v8`。

### F08｜明确区分网络模块、运算过程与特征输出

- **导师意思：** embedding head 目前看不出究竟是网络模块、运算过程还是 embedding 结果；如果要画模块，就应让人看出它的功能；若只画输出，则应明确表示输出向量及其与原子／残基的对应关系。
- **作者回应：** 说明这里本来是网络模块，提出去掉中间特征条；又解释了对点及其邻域进行运算、更新特征的过程。导师继续要求明确表达，未认可仅删一条特征就已解决问题。
- **评价与建议：** 建议采纳。图内采用统一语法：模块用框，特征用张量或特征条，箭头标明变换；原子级和残基级对象按实际模型核对，不因导师举例而改动模型的统计单位。
- **来源：** A 08:17–10:33；并参考第一段外部识别补充。

### F09｜把 density bank 直观表现为密度变换后的多通道表示

- **导师意思：** 读者应从图本身理解 56 channels 大致是什么，而不是读完 Methods 才知道；可以用一个或少数输入密度经过变换得到多个 maps 的方式表现。
- **作者回应：** 解释原本的单通道局部密度块如何变成 56 通道，导师据此提出更直观的表示方向。
- **评价与建议：** 建议采纳直观变换示意；实际来源应同时包括实验密度、受体模拟密度及其派生场，不能为了简化而画成“实验图独自生成全部通道”。56 通道是表示变换，不应误画成 56 个可训练卷积网络。

### F10｜明确 Match 的口袋从哪里来，以及 site 与 pocket 的不同角色

- **导师意思：** Match 中突然出现 pocket，读者看不到来源；应表现由上一步候选区域定位、结合受体结构取得局部口袋的过程。原始输入与当前阶段产物的排布也应更清楚。

### F11｜用可辨认的受体结构或透明表面表现 pocket

## Results 的结构与解释

### R01｜在结果开头用一段话交代测试对象和类别构成

- **导师意思：** 读者先要知道 179 个 map 是什么、包含多少配体实例、有哪些类别，为什么后面区分 all ligands 与小分子；说明与训练集去冗余即可，详细构造过程留到 Methods。提到“一千个”等数字是在举例，不是确定的样本数。
- **作者回应：** 指出已有一些说明写在后面，讨论后认可把必要背景提前的方向；不能据此认为导师要求重新构造数据集。
- **评价与建议：** 优先采纳。用当前冻结统计填写 PDB／map 数、配体实例数和类别数，另明确 77 个 PDB、446 个合格小分子属于 Build 子集。不能把 map、身份、blob、实例混作样本单位。
- **来源：** B 00:00–04:41；辅助提纲的第一项实质结果也以 179 个 ligand-containing maps 开头。

### R02｜评价指标的严格定义移到 Methods，Results 只保留必要的阅读入口

- **导师意思：** 指标定义不是研究结果。Results 应讲研究产生的主要发现，Dice、Precision、Recall、PRAUC 的计算定义可指向 Methods，无须先列大量数学说明。
- **作者回应：** 明确解释自己把定义放在 Results 是担心读者看不懂；这是一项有理由的选择，而非无意写长。
- **评价与建议：** 采纳结构调整，同时保留一句让读者知道指标衡量什么、越高还是越低越好。新定义的实例匹配规则可用短语提示，不把完整公式再搬回结果开头。不能以精简为由省略会改变结论的分母与输入条件。[Nature Communications 官方结构说明](https://www.nature.com/ncomms/submit/article) 将 Results 与 Methods 的职责分开；具体压缩方式仍是写作判断。
- **来源：** B 00:00–04:41、17:52–18:34；D 02:37–03:08。

### R03｜结果解释需要从“分数更高”推进到为什么、何时和什么规律

- **导师意思：** 逐项复述均值及领先幅度是常见但浅的解读；还应分析为什么提升、哪些条件下更好、何时较差。案例是把整体结果解释深入的一种方式。
- **作者回应：** 承认这是写作难点，并说会尽量作进一步分析；提出上下移动案例与统计图的位置。
- **评价与建议：** 优先采纳。每个结果单元形成“主要发现—关键证据—与本实验直接相连的解释”，用已有案例和误差分析解释互补信息、假阳性和密度约束。机制没有被独立检验时，不把合理解释写成已证明因果，也不为每句结果添加 may/could。
- **来源：** C 00:00–04:02。

### R04｜按科学问题组织结果，不必维持当前 Stage 1／2／3 的平铺结构

- **导师意思：** 录音提出重写 Overview、合并 Match 与 Build、把消融单独组织，并让结果与案例共同说明问题。
- **作者回应：** 对 Match 与 Build 合节有明确同意，其他结构仍需形成完整改稿。
- **辅助提纲：** `outline.docx` 依次列出 Overview of LigandSeek、配体密度分割、配体匹配与对接、大复合物应用、运行时间分析、消融研究。这是同目录提纲的内容，不能全部冒充录音中的逐字建议。
- **评价与建议：** 建议把该提纲作为第二轮结构候选；每节先确定要建立的一个结论，再决定图和段落的顺序。运行时间与消融是否独立成节，取决于已有证据量，不自动承诺新增实验。
- **来源：** B 00:54–01:45；D 03:10–04:35；E 01:33–02:29；[辅助提纲](outline.docx)。

- **技术核查：** PRAUC 本身是 precision–recall 曲线下面积，不是 Dice 随阈值变化的简单平均。录音中用 Dice-PRAUC 作口头类比，不宜直接进入论文定义。固定的双向覆盖阈值与用于遍历 PR 曲线的预测置信分数阈值应分开。[scikit-learn 的 PR 曲线定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_curve.html) 支持这一数学区分；本稿的实例匹配规则仍以 Methods 和冻结计算为准。
