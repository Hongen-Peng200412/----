# 图表与实验数字的追溯

每张论文图、每张结果表和每项独立实验数字，都应能沿稳定标识找到直接生成逻辑、实际读取的数据、统计条件和原实验来源。八份 `图表追溯.md` 是唯一人工维护源；PPT 的来源批注由工具从文档完整同步。原生 Markdown 表格和正文数字没有 PPT 副本，不为追溯额外创建 PPT。

## 文件位置与职责

```text
画图/画图代码/
├─ stage1/{calculate,visualization,output}/
├─ stage2/{calculate,visualization,output}/
├─ stage3/{calculate,visualization,output}/
├─ e2e/{calculate,visualization,output}/
└─ archive/{calculate,visualization,output}/
```

顶层只有上述五个目录，每个目录直属子目录只有 `calculate`、`visualization`、`output`。`calculate` 保存统计性质图、结果汇总、表格和独立数字的长期逻辑；`visualization` 保存分子或密度可视化、流程示意及其长期取数逻辑。四个有效阶段的这两个目录各维护一份 `图表追溯.md`，共八份；暂时没有对应图时明确写无当前对象。总览和跨阶段方法图归 `e2e/visualization`。

每张图或联图原则上以 `pptfig` 稳定图名建立子目录，如 `stage1/calculate/stage1-main-sixpanel/`。允许多个相似图共用计算、布局、图注和装配实现，也允许同名目录仅传入稳定图名或病例名。不能为了形式上的自包含复制科学定义。追溯正文及PPT来源批注必须明确：关联的其他稳定图名、共享程序、共同计算或仅共用工具的区别、本图如何选择数据和面板。不得只给一个转发入口让读者自行跳转寻找。源代码及必要的小型配置由 Git 跟踪；`archive` 与各阶段的 `output` 按固定规则忽略，不为每次任务追加例外。

`output` 保存最初的冻结元数据、实际绘图输入、来源原件、外部配置或代码证据及生成留档。不得仅留下指向已删除临时文件的路径。原始结果和来源散列保持原样，目录迁移的原位置与新位置另记留证；路径变化不等于科学内容改变。重绘默认写临时构建目录或 `output/<图名>/regenerated/`，不能覆盖冻结原件。

`temp` 必须可整体清空。它可以承载本次生成的SVG、场景、渲染图、候选PPT、日志及前后步骤之间的中间文件；所有被读取的临时输入必须由同一次运行的前置步骤产生。长期程序、冻结真值、唯一作者素材和运行依赖包不放在temp。依赖包使用固定安装位置，并记录安装方式和版本。

作者继续编辑的正式 PPT 位于 `画图/` 根目录并由 Git 跟踪。PPT 是当前展示和双语图注的维护源；`output` 是生成时的数据留档，二者职责不同。已有正式补充数据归档保留原位，通过追溯记录连接，不重复搬迁其不可变证据。

## 新增或修改实验图表

1. 读取最新稿件、所属 PPT、对应追溯记录和冻结数据，确认作者保存的最新版本。
2. 固定稳定图名或表格、数字标识。图名不使用临时图号；病例用 PDB、配体实例编号和 blob 编号定位，不只用面板字母。
3. 将长期逻辑放入所属 `calculate` 或 `visualization`，将冻结输入、原始结果与来源证据保存在 `output`。临时代码必须满足删除后不影响复现或追溯；任何仍被长期入口导入、执行或读取的代码都不属于临时文件。
4. 更新所属追溯文档，写清共享关系、直接绘图或制表函数、当前版本、真实输入字段、连接键、筛选规则、样本分母、统计定义、原实验版本和完整重建命令。外部原件无法取得时，记录确切路径、已知证据及缺失范围，不把报告摘录写成原始结果已齐备。
5. 新图构建须将 `@@图名` 作为独立批注，备注只保存双语图注。随后执行追溯同步与只读检查；来源批注不能混入图注。
6. 在旧temp不可读的条件下实际运行受影响图的完整重建，覆盖必要的数据准备、绘图／原生渲染、场景运输和PPT装配。只验证PNG或检查路径存在不算完成。核对科学数值与必要几何、图名和备注，候选内同步完整来源批注；已有作者原生素材可作输入，但不能以打包既有实验PNG代替必要的重绘。更新当前PPT前保全作者编辑；需要编译Word时按转换工具规则运行。

在仓库根运行：

```powershell
python -X utf8 -B 转换工具/ops/rebuild_figures.py --figure 稳定图名
python -X utf8 -B 转换工具/ops/rebuild_figures.py --all
python -B 转换工具/ops/figure_provenance.py --sync
python -B 转换工具/ops/figure_provenance.py --check
```

单图命令与`--all`按任务选用，不必重复执行。重建每次创建新的构建目录，对Python、Node及原生渲染脚本屏蔽其他temp内容；失败就报出具体步骤，不回退到旧缓存。新图片、`rebuilt.pptx`和`receipt.json`位于 `temp/figure_rebuild/<运行号>/<图名>/`，正式PPT只读，不重新训练或推理。运行环境与阅读顺序见[重建工具说明](../转换工具/ops/README.md)。

同步器只添加或更新以 `PROVENANCE v1` 开头的专用来源批注，保留原 `@@` 定位批注、作者批注、图形和备注。检查四份稿件的真实 `pptfig` 引用、表格登记、八份文档、入口与函数、输入位置、固定目录结构、共享关系、可静态识别的传递导入及双写内容。`--check`不实际重绘，不能替代上一条完整生成验收。检查报告及写入前备份位于 `temp/`；写入前和替换前检测作者并发保存。自然语言实验断言仍需科学审核。

## 追溯记录格式

每条记录使用固定起止标记，正文必须独立可读。元信息位于 HTML 注释中，由同步器读取；它不构成另一份需要人工维护的数据库。

```markdown
<!-- provenance:begin stage1-main-sixpanel -->
<!-- provenance-meta {"id":"stage1-main-sixpanel","kind":"figure","pptx":"画图/stage1结果.pptx","figure":"stage1-main-sixpanel","entries":[{"path":"画图/画图代码/stage1/calculate/stage1-main-sixpanel/plot_figures.py","symbol":"draw_panel"}],"inputs":["画图/画图代码/stage1/output/stage1-main-sixpanel/v5/data/plot_data.json"],"sharing":[{"path":"画图/画图代码/stage1/calculate/stage1-main-sixpanel","figures":["ligandseek2-vs-ligandseek1"],"purpose":"仅共享SVG显示转换"}],"rebuild":{"script":"转换工具/ops/rebuild_figures.py","figure":"stage1-main-sixpanel"},"status":"local_verified"} -->
## stage1-main-sixpanel｜Stage 1 主结果

本图与@@ligandseek2-vs-ligandseek1仅共享SVG转换，不共同计算模型结果。正文依次解释本图选择、直接生成逻辑、冻结输入与字段、统计范围、原实验版本、完整命令、核验结果和未闭合证据。
<!-- provenance:end stage1-main-sixpanel -->
```

`kind` 为 `figure`、`table` 或 `claim`。图记录必须有 `pptx` 和 `figure`；表记录额外提供整数 `table`，对应当前表号1至4；独立数字使用 `claim`。`entries.path`、`inputs` 使用仓库相对路径，Python 的可选 `symbol` 使用真实 AST 符号，如 `draw_panel`；JavaScript、ChimeraX 等入口在正文写真实函数或命令，不伪造 Python 符号。`status` 说明已核实范围，存在缺口的记录不能标成全部原件齐备。

图记录的`sharing`为共享关系列表，没有共享时显式写`[]`。每项包含实际代码目录`path`、其他已登记图名`figures`和准确用途`purpose`，这些关系必须同时在正文中冷读可见。`rebuild`登记完整重建脚本与稳定图名，新增图时同步补充实际步骤，不能只登记命令而不执行验收。

记录必须把以下事实放在当前条目中：科学对象与评价条件，逐 PDB 或逐实例平均层级，完整分母及失败值处理，Top-1 与 best-of-50 的原排序，单位与阈值，病例身份，源文件与运行版本。来源缺口单列，并区分没有本地副本、没有原始程序、正文与证据口径不同。

## 人工编辑与版本

按作者约定，人工删例、裁切和调版不篡改数据，既有科学来源链继续有效。保存生成时完整病例集合及各病例稳定身份，不能因当前截图与生成图不同就恢复作者删除的病例。校验来源与记录内容，不要求 PPT 整文件散列或截图与 AI 初稿相同。

同一逻辑图的不同统计口径可以复用图名，但追溯必须同时指明当前 PPT 和口径。历史口径或旧图集不是当前原件；不能以当前仓库 HEAD 冒充当时实验实际运行的 release。

## 固定归档操作

作者说“整理画图代码，把无用的代码进行归档”或类似命令时，即执行以下完整操作：读取当前四稿引用和八份记录；扫描代码导入、命令调用、配置与数据读取；从当前入口求依赖闭包；先将仍有价值的临时代码救回活动目录；仅将不属于当前依赖闭包的旧逻辑移入 `archive/calculate` 或 `archive/visualization`，历史生成物进入 `archive/output`。保全归档前原件和迁移清单，不删除历史文件，不按日期或文件名猜测无用。

移动前在 `talk/refactor/` 建立具体文件清单及验证基线；调整有效路径和当前契约文档，历史日志保留当时路径并链接迁移记录。归档完成后运行追溯检查和受影响的实际生成入口；不能让活动代码读取 `archive` 或 `temp` 中的长期依赖。已有 `.gitignore` 固定排除规则应足以覆盖新增归档，不逐任务追加忽略项。
