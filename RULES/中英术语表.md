# 论文中英术语表

本表按科学指涉对象统一正文、图注、表注和图内标签。标准英文用于首次定义及独立说明；只有列出的变体可以在规定范围内替代它。中文全称和简称同样受定义约束。

## 全称与受限变体

- 可以使用规定的全称、简称、单复数及语法要求的大小写，不为避免重复临时增加同义词。方法品牌内部大小写固定。
- Abstract、正文及每个可独立阅读的图注分别给出首次出现时所需定义；图内简称由所属图注定义。正文不反复展开同一缩写。
- 变体只对同一行对象有效。例如 `candidate region` 不等于真实区域，`identity` 不等于一个具体实例。
- 改名先更新本表，再核查两稿、图注和标签。局部翻译只修改指定范围及其依赖，未译章节旧用法列为待同步，不无关地重写全文。
- 代码键、文件名、函数名和既有数学下标原样保留。例如代码 `ligand-area` 可映射到正文 `ligand region`，不为统一文字擅改接口。
- 英文采用英式拼写，如 `modelling`、`normalisation`、`centre`；软件品牌和原始接口拼写保持原文。图内使用正常标签大写。

### 三阶段命名规则

`LigandSeek-Find`、`LigandSeek-Match` 和 `LigandSeek-Build` 是三个阶段的全称，`Find`、`Match` 和 `Build` 是受限简称。全称与简称指向同一阶段，按阅读场景选用，不为避免重复而交替使用。品牌大小写固定为 `LigandSeek`，不写 `Ligandseek`。

| 使用场景 | 命名要求 |
|---|---|
| 正文首次正式介绍三个模块 | 使用全称并明确简称映射，可分别写 `LigandSeek-Find (hereafter Find)`，或集中说明三个全称分别简称为 `Find`、`Match` 和 `Build`。介绍通用任务瓶颈的 `Find bottleneck` 等表达不等于正式模块定义 |
| 已定义模块且框架归属明确的连续正文 | 使用 `Find`、`Match`、`Build`；不必每段或每节重新展开。简称的指涉出现歧义时恢复全称 |
| 与其他方法直接比较、独立性能表格或比较图例 | 使用全称，如 `LigandSeek-Find` 与 `Emap2lig-Find`；不将不同工具的定位模块都简称为 `Find` |
| Abstract 或可独立阅读的图注 | 在该摘要或图注内明确框架归属及全称与简称的对应关系，不能依赖正文中的定义；其后可使用简称 |
| 图内架构或流程标签 | 可用 `Find`、`Match`、`Build`，由所属图注明确归属；性能比较标签采用全称 |
| 阶段与内部网络需要区分 | 使用 `the Find stage`、`the Find network`、`the Match stage`、`the Match network`、`the Build stage` 等描述。描述词只明确层级，不增加模块别名；Build 的具体对接模型使用 `PocketXMol-tuned` 等实际名称，不把可接多个工具的阶段称为一个固定网络 |
| 代码、仓库及接口名称 | 原样保留实际的 `Finder`、`Matcher`、`Builder` 标识；在正文解释这些标识时明确其对应阶段，不将它们作为论文模块名的同义替换 |

例如，在已经定义简称的正文中可写：`Find combines receptor information with experimental density to predict ligand regions.`。明确讨论内部网络时写 `The Find network`，无需改称 `Finder`。

## 未定科学选择

本表不裁定数值矛盾、符号重用或新科学定义。发现未规定的变体、缩写指涉不同对象，或同一数值有不同分母时，在[执行记录](执行记录.md)写明位置、差异和候选处理，向作者汇报。旧图和未译章节用法逐批处理，不自动成为允许变体。
