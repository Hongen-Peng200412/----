# Git 快照与固定 AI 报告规格

本规格覆盖一键式母目录到 Gdrive 副本的手动单向同步。实现和验证记录见 [执行记录.md](执行记录.md)，关系索引见 [映射索引.md](映射索引.md)，字段与入口见 [README.md](README.md)。

1. 母目录为唯一编辑与 Git 操作来源；脚本不回写源文件、索引或提交历史，运行中间文件放入源 `temp/`。
2. 以 `963675351a04a0309509b80759da7a1da4c88306` 为浅历史起点，保留原 SHA 与之后的当前分支历史，省去此前历史；独立副本不依赖母目录 Git 对象。
3. 副本 HEAD、当前分支、原始索引、staged 差异、unstaged 差异、未跟踪文件和实际内容与成功同步时的母目录一致。已跟踪文件不受忽略规则过滤。
4. 固定发布副本 `temp/AI-Git/当前Git改动报告.pdf` 和 Markdown 同内容版，元数据和持久提示词位于同目录；报告与原文件不混入彼此的 Git 状态。
5. 清理开关默认开启，成功发布新报告后清除全部旧报告归档和大体积生成中间文件；关闭时归档旧报告，固定当前路径保持不变。
6. 提示词明确 staged、unstaged 和未跟踪的区分，要求核对快照编号与时间，不根据二进制差异猜测正文内容，也不声称在只有 Drive 访问能力时运行 Git。

验收使用独立临时仓库验证 A／B／C 部分暂存、未提交新 blob、删除、重命名、忽略已跟踪文件、起点以前对象缺失、后续提交 SHA 不变、清理开关和 Git 锁；实际目录再验证一键入口、状态及内容一致，并检查 PDF 渲染。副本多文件发布不提供整体原子事务；源操作并发、特殊索引或绕过基点的历史路径均明确拒绝。
