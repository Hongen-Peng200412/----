## 缺陷的准确含义

需要把三个概念分清：

| 概念 | 已核实含义 |
| --- | --- |
| 推荐 level | EMDB 主图记录中的推荐 contour level，不是通过本测试集搜索得到的最优参数 |
| 自动查询 | 官方文档为 `--emdb-id` 声明了查询功能；官方地图读取函数不会仅凭标准文件名自动查询。本次 runner 已显式传 ID，仍触发缺陷 |
| 有效截断阈值 | `get_unified_mrc()` 默认 `contour_ratio=0.5`，所以实际为推荐 level 的一半；不是两倍 |

官方[输入文档](https://github.com/kiharalab/Emap2lig/blob/e92f19b4f951bed68fd0fc002465db51818ee8bd/docs/input-format.md)说明 `--emdb-id` 应获取推荐 contour，`--contour-level` 可直接给数值。实际[入口](https://github.com/kiharalab/Emap2lig/blob/e92f19b4f951bed68fd0fc002465db51818ee8bd/src/emap2lig/main.py)先执行 `parse_mrc(input_path, emdb_id=emdb_id)`，随后调用 `get_unified_mrc()` 时只传地图对象、裁剪参数和 `cfg.contour_level`，没有传 `emdb_id`。

`parse_mrc()` 只将 ID 保存在 `MapObject.emdb_id`。而[预处理函数](https://github.com/kiharalab/Emap2lig/blob/e92f19b4f951bed68fd0fc002465db51818ee8bd/src/emap2lig/data/map.py)仅在它自己的 `emdb_id` 形参非空、且 `contour_level` 为空时查询，不读取对象中的 ID。因此配置的 `contour_level: null` 会一直进入无推荐 level 的归一化分支。

设原图推荐值为 $L$，重采样后的体素密度为 $m(x)$。显式给出 $L$ 时，官方代码先把负值置零，再把低于 $L/2$ 的值置零；保留值随后按正值体素的第 98 百分位缩放。之后还按非零密度裁剪，因此应用 level 同时可能改变有效内容范围、裁剪尺寸和原点。

旧运行仍执行了重采样、负值清零、第 98 百分位归一化和裁剪；准确名称是“未应用推荐 contour 的预处理”，不能写成“完全没有归一化”。阈值后的归一化不是简单二值化，保留下来的体素仍为连续密度，数值也不保证截断到 1。

应按作者建议，在相同测试集和评价思路下增加一轮显式使用推荐 level 的 Find 与 Find→Build。新分数需由这一轮运行得到，不能提前判断提高或降低。无 level 条件继续作为有效、独立的已完成实验保留，新条件不自动替换主文基线。论文采用哪些结果及放置位置由作者决定，当前优先考虑新增补充材料小节。
