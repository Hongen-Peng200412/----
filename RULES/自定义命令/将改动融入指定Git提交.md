# 将指定修改融入精选Git历史并同步

本命令改变修改在精选历史中的归属，不改变操作开始时的本地文件内容。正式完成必须同时包含获准的本地主线更新、GitHub主线同步、对应服务器全面版本独立恢复及临时材料清空。项目精选/全面Git不是实现/学习双线，不自动创建Learn/CUMULATIVE或长期Work分支。

## 输入与授权

作者说“将当前staged或unstaged修改融入指定commit”或同义表述时执行。只选作者指定的来源：staged读取索引版本，unstaged读取相对索引的修改，两者均指定时合并选定变化；不能以某文件被选中为由吞入其中未获准的其他片段。

选定修改依赖未纳入内容而无法独立放入目标提交时，先说明具体依赖并询问是否扩大输入，不能自动把staged、unstaged或未跟踪文件整包合并。

作者指定提交列表时只处理列表中的归属；明确指定连续区间时展示实际祖先顺序和包含的端点。表述有歧义、目标不可达或不能唯一确定归属时先询问。未指定归属时，可将具名Figure代码融入该图原专属提交；同一修改存在多个合理目标时不能自行决定。

正式调用本项目历史重整命令，包含GitHub `origin` 的获准正式主线及 `/home/penghongen/manuscript_full_history/LigandSeek` 的同步。先核对origin确为论文精选仓库、分支为获准主线；不能把这个规则当成覆盖任意远端、侧枝或服务器科学仓库的许可。作者明确要求只做本地候选时可准备候选，但不能据此移动已发布的正式引用并报告全任务完成。

只读准备阶段列明区间后必须跟随重放的提交。已授权区间有后继时，后继父SHA会改变，必须保持其原有修改、标题及顺序；未获准的侧枝、合并关系、标签、签名、工作树占用或协作者依赖受到影响时，先报告具体引用并取得扩大范围的许可。借鉴双线skill的隔离、拓扑和等价核验，不强行套入其分支命名及学习提交顺序。

## 固定执行顺序

1. **只读检查。** 核对HEAD、分支、目标对象、祖先关系、暂存/未暂存/未跟踪文件、所有相关引用和worktree；读取GitHub正式引用的精确SHA及服务器当前有效版本，确认没有未收口事务。
2. **记录内容基线。** 按[全面同步枚举边界](../../TOOLS/sync-to-server/README.md)枚举项目实体文件和链接，排除根.git与根temp，不跟随链接。记录路径、类型、大小、原字节SHA256、链接目标、HEAD、索引及选定来源。ignored文件、CXS、Word、PPT和.review都纳入内容保护；Git文本过滤后的相等不能代替本地原字节相等。
3. **核实变化。** 区分注释/Docstring与执行语句、配置、参数、异常和产物变化。Python可用去注释的AST比较；Docstring存在反射用途时单独核查。执行顺序等变化必须追到调用方并作必要真实输入比较。不能只凭作者或agent认为等价就跳过，也不能擅自撤销用户认为等价的修改。出现科学数值、成员、排名或画面差异时询问作者；仅序列化顺序不同也必须明确记录。
4. **隔离构造候选。** 在本次temp中使用独立索引、临时仓库或隔离工作树，不在作者工作目录中反复checkout/reset。保持原Figure提交标题和职责，不新增长期旧状态备份。候选中的每项运行相关变化只能来自选定输入，禁止趁机修复、格式化或升级依赖。
5. **核验候选。** 保存旧新提交对应关系，核对各目标及后继提交的父子关系、标题和修改范围。候选终点与应纳入输入一致；未选修改的内容及暂存意图保留。前后全部受保护本地文件原字节相同；只有事先具名的Git追溯文件可例外。检查精选收录规则和全部将推送历史的大文件限制，CXS不能重新纳入。
6. **发布本地引用。** 发布前再次检查基线、HEAD、索引及文件未被并发编辑。用预期旧SHA条件更新获准引用；多引用需使用同一引用事务。不使用reset --hard、清理工作区或重新保存Office文件来制造干净状态。索引只反映已获准纳入的修改，不丢弃未选改动。
7. **同步GitHub。** 使用准备阶段读取的精确远端旧SHA执行条件更新；涉及多个获准远端引用时要求同次原子更新或预先说明可恢复顺序。远端变化时停止，不能自动刷新预期SHA再强推。读回远端正式SHA，必须等于新的本地正式SHA。
8. **同步服务器全面版本。** 保存重整记录后，从当前真实磁盘状态进行普通snapshot，执行独立恢复verify，并用coverage查询新的精选HEAD。要求捕获HEAD/分支/dirty状态正确、完整路径及原字节吻合、删除如实反映，不能以GitHub已成功代替全面验收。
9. **清理并完成。** 全部端点成功后清除本次隔离索引、临时副本/工作树及任务脚本，不新增备份引用，不清理既有归档、reflog或内部对象。根temp须全空。部分任务原样保留未选修改；任务覆盖全部当前修改时，结束工作区必须干净。最终报告本地/GitHub精选SHA、对应全面SHA及验证结果。

## 服务器历史的对应含义

已有全面版本是实际捕获事实，其原`source_head`、捕获时间及文件内容不改写。每次重整保存旧新精选SHA、归属、范围和内容核验结果；建议在人读任务记录 `talk/git/<本次任务>.md` 中维护，作为明确的Git追溯材料纳入精选及全面Git，不保存旧文件副本。

重整后只为实际捕获并验收的完整磁盘状态声明精确覆盖。旧新提交的历史关系对应，不代表旧全面快照与新提交文件逐字节相同；评论被提前融入的新版历史尤其不能用替换source_head制造覆盖。没有完整历史材料的中间提交如实显示未覆盖，不用当前CXS或ignored文件补造过去。当前入口仍只认服务器唯一有效回执。

纯Git历史任务只写论文部署根，不更新实验产物目录中的说明。使用同步套件的 `--document-policy verify` 只读核对明确映射的现有说明；不一致时停止，不借同步修订科学目录。

```powershell
D:/Anaconda/python.exe -X utf8 -B TOOLS/sync-to-server/sync.py snapshot --document-index 追溯文档/source/README.md --document-policy verify
D:/Anaconda/python.exe -X utf8 -B TOOLS/sync-to-server/sync.py coverage --source-head 新的完整精选SHA
D:/Anaconda/python.exe -X utf8 -B TOOLS/sync-to-server/sync.py verify --commit 实际回执中的完整全面SHA
```

## 中断与完成条件

本地、GitHub、服务器不能跨系统原子更新。记录每阶段实际旧新引用及是否成功，读回现场状态后继续同一次操作；不能在一端失败后宣布全部完成，也不能覆盖别人新提交来凑一致。全面传输中断按同步套件同一事务resume，失败捕获只供本次恢复，不成为长期备份。存在未恢复事务时不能清空其必要材料并声称任务完成；若审批阻止清理，明确列出实际残留并请求作者处理。

重整记录不硬编码自己最终提交的SHA，最终GitHub及全面回执在完成消息和现场coverage中核对，避免为记录自身SHA不断追加尾部提交。工作流只规定运维步骤，不拥有科学筛选、评价或Figure绘图规则。
